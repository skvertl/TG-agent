# Домашнее задание: RAG для AI-агента

## Цель

В предыдущем задании вы реализовали AI-агента, с которым пользователь взаимодействует через Telegram.

В этом задании необходимо расширить агента и научить его **работать с документами пользователя**.

Пользователь должен иметь возможность отправить документ Telegram-боту, после чего задавать вопросы по его содержимому.

Поддерживаемые форматы:

- `.txt`
- `.md`
- `.docx`
- `.pdf`

Для поиска информации необходимо реализовать собственный **RAG (Retrieval-Augmented Generation)** pipeline с использованием **SQLite + sqlite-vec**.

---

# 1. Пользовательский сценарий

Пользователь отправляет боту документ:

```text
company_policy.pdf
```

Бот должен сообщить о начале обработки:

```text
📄 Документ получен.

Начинаю обработку...
```

После успешной индексации:

```text
✅ Документ готов.

Теперь вы можете задавать вопросы по документу.
```

После этого пользователь может спросить:

```text
Сколько дней оплачиваемого отпуска предусмотрено для сотрудников?
```

Агент должен найти соответствующую информацию в документе и ответить пользователю.

Ответ должен содержать источник:

```text
В компании предусмотрено 25 дней оплачиваемого отпуска в год.

Источник: company_policy.pdf
```

# 2. Архитектура

Необходимо реализовать следующий pipeline:

```text
                 Telegram
                    │
                    ▼
             ┌─────────────┐
             │    Agent    │
             └──────┬──────┘
                    │
             User question
                    │
                    ▼
             ┌─────────────┐
             │   Embedding │
             └──────┬──────┘
                    │
                    ▼
             ┌─────────────┐
             │  sqlite-vec │
             └──────┬──────┘
                    │
                 Top-K
                  chunks
                    │
                    ▼
             ┌─────────────┐
             │     LLM     │
             └──────┬──────┘
                    │
                    ▼
                 Telegram
```

Для загрузки документа pipeline выглядит следующим образом:

```text
Telegram document
       │
       ▼
Download file
       │
       ▼
Extract text
       │
       ▼
Chunking
       │
       ▼
Generate embeddings
       │
       ▼
SQLite + sqlite-vec
```

# 3. Поддержка документов

Бот должен поддерживать следующие форматы:

| Формат | Требование |
|---|---|
| `.txt` | обязательно |
| `.md` | обязательно |
| `.docx` | обязательно |
| `.pdf` | обязательно |

Для каждого формата необходимо извлечь текст.

Можно использовать специализированные библиотеки для работы с PDF и DOCX.

**Не требуется самостоятельно реализовывать PDF/DOCX parser.**

# 4. Chunking

После извлечения текста документ необходимо разделить на небольшие фрагменты — chunks.

Например:

```text
Document
   │
   ├── Chunk 1
   ├── Chunk 2
   ├── Chunk 3
   ├── Chunk 4
   └── ...
```

Размер chunk и overlap необходимо выбрать самостоятельно.

В README необходимо объяснить:

- какой размер chunk вы выбрали;
- какой overlap используете;
- почему выбрали именно такие значения;
- какие проблемы могут возникнуть при слишком маленьких или слишком больших chunks.

---

# 5. Embeddings

Для каждого chunk необходимо получить embedding.

Например:

```text
"This company provides 25 vacation days..."
                    │
                    ▼
              Embedding model
                    │
                    ▼
        [0.123, -0.42, 0.87, ...]
```

Embedding model можно выбрать самостоятельно.

В README необходимо указать:

- название модели;
- размер embedding vector;
- почему выбрали эту модель.

Модель может работать локально или через API.

---

# 6. SQLite + sqlite-vec

Embeddings необходимо хранить в SQLite с использованием **sqlite-vec**.

Минимально необходимо хранить информацию о:

### Documents

```text
documents
---------
id
user_id
filename
file_type
created_at
```

### Chunks

```text
chunks
------
id
document_id
chunk_index
text
```

### Vectors

Для vector search необходимо использовать `sqlite-vec`.

Конкретную структуру таблиц можно выбрать самостоятельно.

Важно, чтобы по результату vector search можно было определить:

```text
vector
   ↓
chunk
   ↓
document
   ↓
filename
```

# 7. RAG

При вопросе пользователя агент должен выполнять retrieval.

Например:

```text
User:
"Сколько дней отпуска я могу взять?"
        │
        ▼
Generate query embedding
        │
        ▼
sqlite-vec search
        │
        ▼
Top-K relevant chunks
        │
        ▼
Build context
        │
        ▼
LLM
        │
        ▼
Answer
```

Необходимо выбрать значение `K` самостоятельно и объяснить выбор в README.

---

# 8. Agent должен использовать RAG как Tool

RAG не должен быть просто огромным текстом, который всегда добавляется в system prompt.

Агент должен иметь возможность использовать поиск по документам как отдельный инструмент.

Например:

```python
search_documents(query)
```

Агент должен самостоятельно определить, когда ему необходимо воспользоваться этим инструментом.

Например:

```text
User:
Какие требования предъявляются к отпуску?

Agent:
→ использует search_documents()

Agent:
→ получает релевантные chunks

Agent:
→ формирует ответ
```

---

# 9. Несколько документов

Пользователь должен иметь возможность загрузить несколько документов:

```text
employee_handbook.pdf
vacation_policy.pdf
benefits.md
```

После этого поиск должен выполняться по **всем документам данного пользователя**.

Например:

```text
User:
Какие дополнительные выходные предусмотрены
для сотрудников?

Agent:
→ search_documents()

→ employee_handbook.pdf
→ vacation_policy.pdf
→ benefits.md

→ LLM

→ Answer
```

---

# 10. Изоляция пользователей

Это обязательное требование.

Документы одного пользователя **никогда не должны использоваться при ответе другому пользователю**.

Например:

```text
User A
 └── secret.pdf


User B
 └── public.pdf
```

Если User B задаёт вопрос, поиск должен выполняться только среди документов User B.

Нельзя выполнять поиск по всем chunks без фильтрации владельца.

Неправильно:

```sql
SELECT ...
FROM chunks
```

Правильная архитектура должна учитывать:

```text
user_id
    ↓
documents
    ↓
chunks
    ↓
vector search
```

Необходимо продемонстрировать это в коде и описать в README.

# 11. Telegram-команды

Добавьте минимум две команды.

## `/documents`

Показывает документы пользователя.

Например:

```text
📚 Your documents:

1. employee_handbook.pdf
2. vacation_policy.pdf
3. benefits.md
```

## `/delete`

Позволяет удалить документ.

Например:

```text
/delete vacation_policy.pdf
```

После удаления должны быть удалены:

- информация о документе;
- chunks;
- embeddings.

После удаления документ не должен участвовать в RAG search.

# 12. Обработка ошибок

Бот не должен падать при ошибках.

Необходимо обработать как минимум:

- неподдерживаемый формат файла;
- повреждённый PDF;
- повреждённый DOCX;
- пустой документ;
- слишком большой документ;
- ошибка embedding model;
- ошибка SQLite;
- ошибка LLM;
- timeout;
- ошибка Telegram API.

Пользователь должен получать понятное сообщение вместо stack trace.

Например:

```text
❌ Не удалось обработать документ.

Пожалуйста, убедитесь, что файл не повреждён.
```

---

# 13. Source attribution

Ответы RAG должны содержать информацию об источнике.

Минимально:

```text
Источник: vacation_policy.pdf
```

Желательно указывать также страницу PDF, если эта информация доступна:

```text
Источник: vacation_policy.pdf, стр. 12
```

или chunk:

```text
Источник: vacation_policy.pdf, chunk #37
```

---

# 14. Если ответа нет в документах

Агент не должен выдумывать ответ.

Если релевантной информации в документах нет, необходимо сообщить об этом пользователю.

Например:

```text
Я не нашёл этой информации в загруженных документах.
```

Нельзя использовать общие знания LLM и выдавать их как информацию из документа.

# 18. Ограничения

## Обязательно

RAG pipeline необходимо реализовать самостоятельно.

Можно использовать библиотеки для:

- PDF parsing;
- DOCX parsing;
- Markdown parsing;
- embeddings;
- SQLite;
- sqlite-vec;
- Telegram API;
- LLM API.

## Не рекомендуется

Не используйте готовые фреймворки, которые полностью скрывают RAG pipeline, например:

```text
Document → Framework → Answer
```

Вы должны самостоятельно реализовать как минимум:

```text
document loading
      ↓
text extraction
      ↓
chunking
      ↓
embedding
      ↓
vector storage
      ↓
retrieval
      ↓
context construction
      ↓
LLM
```
