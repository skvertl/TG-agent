# Proposal: Extensible Async Telegram-Ollama Gateway (Stateless)

## 1. Overview & Objectives
Создание легковесного, расширяемого и надежного Telegram-шлюза на базе Python 3.11+ с плагинным инференсом через локальную модель в Ollama (`qwen2.5:1.5b` или `tinyllama`), функционирующего в строго Stateless-режиме (одноразовый запрос-ответ без сохранения истории между сессиями). Вся система изолирована и оркестрируется через Docker Compose.

---

## 2. Архитектурные границы (Hexagonal Architecture / Ports & Adapters)

Система построена по гексагональной архитектуре, гарантирующей полную независимость бизнес-логики от внешних фреймворков и библиотек инференса:

```
+-------------------------------------------------------------------------+
| DRIVING ADAPTERS (Входные)                                             |
| - TelegramBotAdapter (aiogram 3.x)                                      |
| - CLI / API (будущее расширение)                                        |
+------------------------------------+------------------------------------+
                                     |
                                     v
+------------------------------------+------------------------------------+
| CORE DOMAIN (Доменное ядро)                                             |
| - Contracts / DTOs (ChatMessage, PromptPayload, AgentResult)            |
| - Ports (BaseLLMPlugin, BaseMemoryStore)                                |
| - Exceptions (LLMTimeoutError, LLMConnectionError, LLMResponseError)    |
| - AgentRunner (Оркестрация процесса инференса)                         |
+------------------------------------+------------------------------------+
                                     |
                                     v
+------------------------------------+------------------------------------+
| DRIVEN ADAPTERS (Выходные)                                             |
| - OllamaPlugin (реализация BaseLLMPlugin через httpx.AsyncClient)       |
| - StatelessMemoryStore (реализация BaseMemoryStore)                     |
+-------------------------------------------------------------------------+
```

### 2.1. Driving Layer (Входной)
- **TelegramBotAdapter (`adapters/telegram/`)**:
  - Построен на `aiogram 3.x`.
  - Отвечает за прием команд (`/start`, `/help`) и текстовых сообщений.
  - Управляет фоновой индикацией статуса `typing` во время ожидания генерации ответа.
  - Реализует безопасный чанкинг длинных ответов (лимит Telegram 4096 символов, безопасный порог 4000) с сохранением целостности слов и Markdown-разметки.
  - Преобразует исключения доменного ядра в понятные человекочитаемые ответы пользователю.

### 2.2. Core Domain Layer (Ядро)
- **Сущности и DTO (`core/models.py`)**: Чистые Pydantic V2 модели без привязки к Telegram или Ollama.
- **Порты (`core/ports/`)**: Абстрактные интерфейсы `BaseLLMPlugin` и `BaseMemoryStore`.
- **Оркестратор (`core/runner.py`)**: `AgentRunner` выполняет пайплайн: сборка контекста из памяти -> подготовка промпта -> вызов плагина инференса -> возврат результата.
- **Исключения (`core/exceptions.py`)**: Иерархия доменных ошибок.

### 2.3. Driven Layer (Выходной)
- **OllamaPlugin (`adapters/llm/ollama_plugin.py`)**:
  - Взаимодействует с REST API Ollama (`/api/chat` или `/api/generate`) через неблокирующий `httpx.AsyncClient`.
  - Транслирует ошибки сети (`httpx.ConnectError`), таймауты (`httpx.TimeoutException`) и ошибочные HTTP-статусы в строго типизированные доменные исключения.
- **StatelessMemoryStore (`adapters/memory/stateless.py`)**:
  - Реализация `BaseMemoryStore`, поддерживающая работу без сохранения истории между сессиями (возвращает пустой контекст при запросе истории диалога).

## 3. Нефункциональные требования (NFR)

1. **Отказоустойчивость и защита Event Loop**:
   - Строгий запрет на блокирующие вызовы (sync I/O) в цикле событий asyncio.
   - Таймаут инференса: 60.0 секунд (настраивается через переменные окружения).
   - Graceful shutdown с обработкой `SIGINT` и `SIGTERM`, корректным закрытием пула соединений `httpx` и отменой активных задач бота.
2. **Ограничения Telegram API**:
   - Чанкинг сообщений длиннее 4000 символов с делением по параграфам `\n\n`, строкам `\n` или пробелам, с автоматическим закрытием и повторным открытием незакрытых блоков кода Markdown.
   - Периодическая посылка действия `ChatAction.TYPING` (интервал 4.5 с) в защищенном `try...finally` блоке для гарантированной отмены фоновой задачи.
3. **Безопасность**:
   - Запуск внутри контейнера от непривилегированного пользователя `appuser` (UID 10001).
   - Токены и URL передаются строго через переменные окружения (`.env`), с валидацией через `pydantic-settings`.

## 4. Топология Docker и инфраструктура

```
                           +------------------------+
                           |     Host Network       |
                           +-----------+------------+
                                       | (Port 80/443 outbound to Telegram)
                                       v
                     +------------------------------------+
                     | Docker Bridge Network: ai-network  |
                     |                                    |
                     |  +------------------------------+  |
                     |  | Container: bot               |  |
                     |  | - Python 3.11-slim           |  |
                     |  | - Non-root user (appuser)    |  |
                     |  +--------------+---------------+  |
                     |                 |                  |
                     |                 | http://ollama:   |
                     |                 | 11434            |
                     |                 v                  |
                     |  +------------------------------+  |
                     |  | Container: ollama            |  |
                     |  | - GPU Passthrough (NVIDIA)   |  |
                     |  | - Healthcheck: /api/version  |  |
                     |  | - Volume: ollama_data        |  |
                     |  +------------------------------+  |
                     +------------------------------------+
```

1. **Сетевая изоляция**:
   - Пользовательская bridge-сеть `ai-network`.
   - Контейнер `ollama` не пробрасывает порт 11434 наружу на хост (если не требуется отладка), доступен только сервису `bot`.
2. **Healthcheck & Порядок запуска**:
   - Для `ollama` настроен healthcheck через `curl` эндпоинта `/api/version`.
   - Сервис `bot` запускается с директивой `depends_on: ollama: condition: service_healthy`.
3. **GPU Ускорение**:
   - Резервация NVIDIA GPU через `deploy.resources.reservations.devices`.
   - Полная совместимость с CPU-режимом при отсутствии GPU.
4. **Персистентность**:
   - Именованный том `ollama_data` смонтирован в `/root/.ollama` для сохранения загруженных весов моделей (`qwen2.5:1.5b` / `tinyllama`).
